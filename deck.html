Matchbook — IDEATHON submission3 / 10
solution — three primitives

Matchbook = Proof-of-Invoice + Auto-match + Dispute rails

① Proof-of-Invoice binding

A Token-2022 transfer-hook program + Pay/memo convention that embeds a canonical invoice hash into the transfer itself. The binding is enforced by the protocol at settlement time — not typed in afterwards by a bookkeeper. Impossible to do this way on EVM; native to Solana.

② Auto-match engine

An indexer that watches bound transfers and your ledger (QuickBooks/Xero export or plain CSV), then matches invoice ↔ payment ↔ payout batch in real time. Sub-second settlement on Solana means reconciliation happens with the payment, not weeks later. Exposed as a web app + API + webhooks.

③ Dispute & refund rails

A small escrow PDA (program-derived account) holds payment state per invoice: partial payments, refund windows, dispute flags — the TradFi primitives stablecoin invoicing never had. Same rails serve x402-style agent purchases that today have no recourse path.

Matchbook — IDEATHON submission4 / 10
technicalApproach

Buildable in one hackathon — three components, all boring by design

Anchor program

Token-2022 transfer hook (Rust/Anchor): verifies invoice hash exists in a Matchbook registry PDA before allowing transfer of a configured mint. Fallback mode: Pay-protocol memo parsing for wallets that skip hooks. ~600 LOC, testable on validator locally.

Indexer + matcher

Geyser/websocket stream → Postgres → deterministic matcher (invoice hash exact match first, amount+payee heuristic second, confidence score surfaced). Serves REST + webhooks.

Dispute PDA

Escrow account per invoice: partial-pay state machine (partial → complete → disputed → refunded). Refund = signed claim back to source; dispute = freeze + evidence hash attached. Deliberately minimal — no oracle, no court.

Hackathon scope (5 days)

Day 1–2 hook program + local tests → Day 3 indexer + matcher demo → Day 4 QuickBooks CSV round-trip → Day 5 x402 receipt demo: agent buys an API call, receipt reconciles itself. All on devnet, all open source.

Reuses proven Solana building blocks: Token-2022 hooks (shipping since 2024), Geyser plugins, Anchor. No new consensus, no oracle dependency.

Matchbook — IDEATHON submission5 / 10
the wedge nobody is building: receipts for machine payments

Agents settle in USDC but leave no paper trail

2026 shipped the rails: Pay.sh (Solana Foundation × Google Cloud, May 2026), x402 on SVM, Circle Agent Stack with $0.000001 nanopayments. What none of them define:

  • Receipts — a payment record a finance system (human or agent) can consume
  • Refunds/disputes — push-based payments with zero recourse
  • Budget reconciliation — an agent with a $50/day mandate can't produce a matched expense log

The same three Matchbook primitives solve this. Human AP teams and AI agents need the identical thing: settlement truth.

Skyfire — $9.5M raised, Coinbase Ventures & a16z — ceased operations early 2026 chasing proprietary agent identity. Lesson: the open layer everyone needs is not identity, it's the boring ledger. (archtools.dev migration post, Mar 2026)

Chainalysis counted 100M+ agentic transactions on Base through Q1 2026 — but notes most was farming bots, real commerce ~$28K/day. Speculation happens because real business rails don't. Receipts + disputes are what converts bot traffic into actual commerce. (chainalysis.com x402 adoption, Jun 2026)

Team $49/mo: unlimited matching, QuickBooks/Xero sync, webhooks, dispute console.
Enterprise: custom mints, private indexer, SOC 2 track (Request Finance charges $300–1,500/mo for the suite — room to undercut with focus).

Dispute-rail fees

0.1% on value settled through escrow PDA (refunds, partial payments, x402 receipt flows). At $650B/mo chain volume, capturing even 0.001% of B2B flows is $6.5M/yr run-rate.

Why this compounds

Reconciliation data is the wedge; the ledger it creates becomes the accounting system of record for stablecoin-native businesses — and the only structured expense data source for the agent economy. Data network effects: more matched payments → better heuristics → more matching.

Beachhead GTM

Streamflow + Sphere user base as distribution partners; publish the invoice-hash convention as an open standard other Solana payment tools adopt (network standard beats proprietary — the Skyfire lesson).
